# نظام إدارة الطلبات (Kata)

## مبدأ العمل

هذا النظام هو تطبيق لإدارة الطلبات مبني على Spring Boot، يعمل وفق مبادئ البرمجة التفاعلية (Reactive Programming) ويوفر واجهة برمجية RESTful لإدارة طلبات العملاء وتسليم المنتجات.

## المكونات الأساسية

### 1. نظام الطلبات (Order System)
النظام يدير دورة حياة الطلب الكاملة من الإنشاء حتى التسليم، مع التحقق من صحة البيانات والقواعد التجارية.

### 2. أنواع التسليم (Delivery Types)

النظام يدعم أربعة أنواع من التسليم:

- **DRIVE**: الاستلام من النقطة - فترات زمنية محددة صباحاً (09:00-12:00)
- **DELIVERY**: التوصيل العادي - فترات زمنية محددة عصراً (14:00-17:00)
- **DELIVERY_TODAY**: التوصيل في نفس اليوم - فترات مسائية (17:00-19:00)
  - القيد: لا يمكن الطلب بعد الساعة 4 مساءً
- **DELIVERY_ASAP**: التوصيل السريع - خلال ساعتين من وقت الطلب

### 3. التحقق من الفترات الزمنية (Time Slot Validation)

النظام يتحقق تلقائياً من:
- صحة نوع التسليم المختار
- توافق الفترة الزمنية مع نوع التسليم
- القيود الزمنية (مثل قيد الساعة 4 مساءً للتوصيل اليومي)

## المبادئ التقنية

### البرمجة التفاعلية (Reactive Programming)
النظام يستخدم Project Reactor (Mono/Flux) لتوفير:
- معالجة غير متزامنة (Asynchronous Processing)
- قابلية التوسع (Scalability)
- أداء عالي (High Performance)
- إدارة أفضل للموارد

### معمارية REST مع HATEOAS
- واجهات برمجية واضحة ومنظمة
- روابط ديناميكية (Hypermedia Links)
- سهولة التكامل مع الأنظمة الأخرى

### قاعدة البيانات
- PostgreSQL للبيئة الإنتاجية
- H2 للاختبارات
- Spring Data JPA لإدارة البيانات

## القواعد التجارية (Business Rules)

### قاعدة التوصيل في نفس اليوم
```
إذا كان نوع التسليم = DELIVERY_TODAY
  إذا كانت الساعة الحالية >= 16:00
    رفض الطلب مع رسالة: "لا يمكن التوصيل في نفس اليوم"
```

### قاعدة التوصيل السريع
```
إذا كان نوع التسليم = DELIVERY_ASAP
  وقت البدء = الآن
  وقت الانتهاء = الآن + ساعتين
```

### قاعدة التحقق من الفترات الزمنية
```
لكل نوع تسليم:
  استرجاع الفترات المتاحة من الإعدادات
  التحقق من أن الفترة المختارة موجودة في القائمة
  إذا لم تكن موجودة: رفض الطلب
```

## هيكل البيانات

### الطلب (Order)
- معرف الطلب
- المنتجات (علاقة متعددة)
- العميل (علاقة واحدة)
- نوع التسليم
- الفترة الزمنية
- تاريخ الطلب
- تاريخ بداية ونهاية التسليم
- الحالة

### العميل (Client)
- المعلومات الشخصية
- العنوان
- تفاصيل الاتصال

### المنتج (Product)
- الاسم والوصف
- السعر
- الكمية المتاحة

## التكامل والمراسلة

النظام يدعم Apache Kafka للمراسلة غير المتزامنة بين الخدمات، مما يوفر:
- فصل المكونات (Decoupling)
- قابلية التوسع الأفقي
- موثوقية في نقل الرسائل

## الأمان (Security)

النظام يستخدم:
- Spring Security
- OAuth2 Resource Server
- JWT للمصادقة والتخويل

## نقاط النهاية الرئيسية (API Endpoints)

- `GET /api/orders` - استرجاع جميع الطلبات
- `POST /api/orders` - إنشاء طلب جديد
- `GET /api/orders/{id}` - استرجاع طلب محدد
- `GET /api/orders/stream` - تدفق الطلبات (Server-Sent Events)

## مبدأ عمل الوكيل (Agent Principle)

النظام يعمل كوكيل ذكي (Intelligent Agent) يقوم بـ:

1. **الاستقبال**: استقبال طلبات العملاء عبر API
2. **التحقق**: التحقق من صحة البيانات والقواعد التجارية
3. **المعالجة**: معالجة الطلب بشكل تفاعلي وغير متزامن
4. **التنسيق**: تنسيق الفترات الزمنية حسب النوع المختار
5. **الاستجابة**: إرسال النتيجة مع الروابط ذات الصلة
6. **الإشعار**: إرسال إشعارات عبر Kafka للأنظمة الأخرى

هذا المبدأ يضمن:
- تجربة مستخدم سلسة
- معالجة موثوقة للطلبات
- تطبيق القواعد التجارية بشكل متسق
- قابلية التوسع والصيانة
